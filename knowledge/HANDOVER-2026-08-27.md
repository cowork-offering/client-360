## Architecture note (Fabian's question today, answered + agreed)

Artifacts stay the demo surface through Dreamforce (proven, wired, freeze in days). MCP-native UI
(MCP Apps) would require a second, self-hosted MCP server fronting the Salesforce one, because
McpServerDefinition serves tools only, no ui:// resources. That fronting server is the RIGHT
post-Dreamforce product architecture (portable across hosts; the credit-memo Experience MCP already
proves the pattern; it IS Connectry's product shape) — but it reopens the auth story (today: banker's
own OAuth, run-as-user, no middleman). Post-show track; Clawdy gates it (direction-locking).
