### What the org demanded / refused — findings

1. **`RecordTypeId` was refused.** First attempt on Fee 1 with `RecordTypeId = 012bb000000NNdqAAG` ("Fees") returned
   `INVALID_CROSS_REFERENCE_KEY — Record Type ID: this ID value isn't valid for the user`.
   Three active Fee record types exist (Adjustments `012bb000000NNdoAAG`, Costs `012bb000000NNdpAAG`, Fees `012bb000000NNdqAAG`) but **none is assigned to the integration user's profile.** Records were created with `RecordTypeId = null`. The picklist field `LLC_BI__Record_Type__c` ("Fees"/"Costs"/"Adjustments") is a separate, independently settable field and was used instead. *If the demo UI keys off record type, this needs a profile fix — I did not change any config.*

2. **Percentage fees require two extra fields.** Active VR `Percentage_Fee_Required_Fields`:
   `ISPICKVAL(LLC_BI__Calculation_Type__c,'Percentage') && (ISPICKVAL(LLC_BI__Basis_Source__c,'') || ISNULL(LLC_BI__Percentage__c))`.
   So Percentage ⇒ **`LLC_BI__Basis_Source__c` must be set** (only legal values: `LLC_BI__Amount__c`, `LLC_BI__Scenario_Amount__c`) **and `LLC_BI__Percentage__c` must be non-null.**

3. **The org computes the money for percentage fees.** On insert with `Basis_Source = LLC_BI__Amount__c`, nCino's `FeeTrigger` populated `LLC_BI__Basis_Amount__c` from the loan amount and derived `LLC_BI__Amount__c`:
   - Fee 1: Basis 15,000,000 × 0.50% → Amount **75,000**
   - Fee 4: Basis 12,000,000 × 0.25% → Amount **30,000**
   Do not hand-set `LLC_BI__Amount__c` on percentage fees.

4. **TRID rules did not fire.** Four active TRID validation rules (`Fee_Disclosure_Tolerances_Categories`, `Credit_Disclosure_Tolerances_Categories`, `Negative_Trid_Fee`, `Service_Shopped_For`) all gate on
   `LLC_BI__Loan__r.LLC_BI__Product_Reference__r.LLC_BI__Product_Feature__r.LLC_BI__Is_Subject_To_TRID_Tolerances__c`.
   Verified **false** on the LoC, Equipment and Construction products, so no TRID category fields were needed. This will change if a consumer product is used.

5. **`Name` is an autonumber** (`FEE-00000n`) — not settable. Use `LLC_BI__Fee_Type_Description__c` (255 chars) for the human label.

6. **Paid-By picklist is closing-oriented, not C&I.** Legal values are only `Bank Paid | Financed from Proceeds | Paid Outside Closing | Paid by Seller | Waived`. There is no "Borrower Paid". `Financed from Proceeds` was chosen as the closest C&I-realistic value. Consequence: the VRs `Lender_Paid_Fee_Types`, `Seller_Paid_Fee_Types` and `Exclude_Seller_Paid_Fee_From_APR` reference picklist values ('Lender', 'Seller', 'Other') that **do not exist in the active picklist** — those rules are effectively dead in this org.
